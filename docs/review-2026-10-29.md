# 2026-10-29 全面测试与修复报告

## 1. 背景与范围

用户反馈：在连续编辑面（Typora 模式）中，列表存在时用 Enter 消除当前行列表格式后，再输入
```` ``` ```` 并回车插入代码块会失效。本轮以该问题为起点，对全部 Markdown 语法与快捷键执行
**单独 / 组合 / 交叉组合**三级验证：

- 列表（无序 / 有序 / 任务 / 嵌套）退出后插入代码块（```` ``` ````、`~~~`、语言联想、菜单插入）。
- 代码块全生命周期：围栏种类、语言与高亮、缩进代码、引用 / 列表内代码、未闭合围栏、
  内嵌围栏、Mermaid、删除 / 撤销、与表格 / 公式 / Front Matter / TOC 相邻组合。
- 快捷键：连续面内格式键、代码块 / 表格专用键、Backspace 去格式、主窗口菜单接线、
  源码模式格式键、真实 `Ctrl+/` 模式切换。
- 全语法复合文档的往返保真与二次渲染幂等。

基线 `0.3.14`（`b69bbd5`）。本轮只修改编辑器与渲染管线，未改版本号、安装包或更新清单，
未执行真实安装 / 升级。

## 2. 发现并修复的问题

### P0：退出列表后「围栏 + 回车」不生成代码块（用户反馈，已修复）

**根因（两处）**：

1. 在空列表项上按 Enter 退出列表时，Chromium 在列表后插入的是裸 `<div>`（不是 `<p>`），
   而 Enter 围栏转换规则与围栏语言联想只查找 `closest("p")`（`app.js`），宿主找不到，
   回车走默认分支，三个反引号被当作正文，保存时转义成 `` \`\`\`python ``。
2. 即便识别到宿主，Chromium 对选中 `<div>` 执行 `insertHTML` 时会把新代码块**嵌套进 div**
   （选中 `<p>` 则是替换），导致代码块被序列化成工具栏文字 + 空代码跨度。

**修复**（`mdnote/editor/web/app.js`）：

- 新增 `fenceHost()`：接受 `<p>` 与浏览器生成的顶层裸 `<div>`，排除列表项 / 代码 /
  表格 / 原子内部；Enter 围栏规则、语言联想、提示关闭统一使用它。
- `insertFenceCode()` 在插入前把裸 `<div>` 规范化为 `<p>`，保证替换而非嵌套。

回归：`tests/test_list_code_cross.py`（13 项真实 QTest 键驱动）。

### P1：引用 / 列表内围栏保存时被破坏（交叉验证新发现，已修复）

Python-Markdown 的 `fenced_code` 不解析引用与列表项内部的围栏，反引号围栏被降级成
*行内* `<code>`，反向序列化后围栏线消失（`> ```py … > ```` → `` > `py … > x` ``）；
波浪号围栏仅作为惰性正文幸存，也不能渲染为代码。

**修复**（`mdnote/services/surface.py`）：新增 `_contains_nested_fence()`，引用 / 列表块
内含围栏（含 `> > ` 嵌套、列表内引用围栏）时整体渲染为逐字 `atom-structure`
（点击进入源码编辑，`data-md` 逐字保留），保存零改写；列表 8 空格缩进代码原本即可正常
渲染，继续走普通路径。

### P1：引用定义过度原子化，连带段落内行内公式不渲染（交叉验证新发现，已修复）

文档中只要存在引用 / 脚注 / 缩写定义，**任何**含 `[…]` 的段落（包括普通行内链接
`[文字](url)`）都被整体原子化，导致段落失去行内编辑且其中 `$x=1$` 不被包装渲染。

**修复**（`surface.py`）：新增 `_definition_labels()` / `_uses_definition()`，只原子化
真正引用已定义标签的段落（`[label]`、`[text][label]`、`[^label]`、缩写词整词出现），
普通行内链接保持为可编辑段落。

### P2：代码块前 Delete 反向删除正文（已修复）

光标在紧邻代码块的段落 / 标题 / 引用末尾按 Delete，Chromium 无法并入代码块的嵌套编辑宿主，
异常地把**本段自身文字**清空（代码块纹丝不动）。新增 `guardDeleteIntoCode()`：折叠选区
位于块末且下一个兄弟节点是代码块时拦截 Delete。反方向（代码块后一段开头 Backspace）
原生行为已安全，保持不变。

### P2：空代码块缺少键盘删除路径（已优化）

代码块是 `contenteditable=false` 外壳 + 嵌套编辑区，空块内 Backspace 无任何效果，
用户只能用鼠标选中整块删除。新增 Typora 式行为：代码正文为空且光标在 0 列时 Backspace
整块删除（`removeCodeBlock()`）：

- 前方有正文块：一次原生可撤销事务，删除后相邻段落保持空行分隔，光标落到前段末尾；
- 代码块位于文档开头 / 前面只有原子：结构性删除，光标进入后一块（相邻代码块进入其编辑区
  0 列；无任何正文时留下空段落）。
- Mermaid 空块行为一致。

### P3：引用开头 Backspace 不去格式（已修复）

`blockquote > p` 的结构换行使 `Range.toString()` 在块首多返回一个 `\n`，偏移量恒为 1，
Backspace 去格式判定失效。新增 `_atBlockTextStart()`，比较时忽略块边界换行；
标题 / 列表行为不变。

### P3：Ctrl+K 无选区时链接占位文字丢失（已修复）

菜单「链接」直接调用 `wrapSelection`，绕过了 `insertLink` 的占位逻辑，无选区时插入
空的 `[](https://)` 且方括号被转义。新增 `EditorSession.insert_link()`（连续 / 源码两模式），
菜单与 `Ctrl+K` 统一走该入口；连续面正确插入并渲染 `[链接文字](https://)`。

## 7. 已知限制与边界

- 引用 / 列表内围栏因引擎限制**不能所见即所得编辑**，以逐字原子呈现（点击源码编辑）；
  保存内容与原文逐字一致。8 空格缩进代码仍走正常渲染路径。
- 代码块前 Delete 仅在「折叠光标位于块末 + 紧邻代码块」时拦截；跨块选区删除使用原生行为
  （选中代码块按 Delete 仍可删除，相邻段落会被原生合并，与图片 / 分隔线删除行为一致）。
- 文档开头空代码块的结构性删除不走原生撤销栈（Chromium 拒绝对首原子执行编辑事务）；
  前文有正文块的删除可正常 Ctrl+Z。
- IME 输入沿用事件模拟验证，未接真实输入法逐一测试；离屏测试不代表真实显卡输入延迟。
