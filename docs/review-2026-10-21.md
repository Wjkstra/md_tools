## 2. 必须优先处理的 P1

### P1-01：页面未就绪时，保存成功却清空已有文件

位置：[webview.py:175](../mdnote/editor/webview.py#L175)、[editor_session.py:260](../mdnote/ui/editor_session.py#L260)。

1. 临时文件原文为 `# Important saved content`，页面已初始化。
2. 将页面置于未就绪状态 `App.surfaceReady=false`，模拟重建/异常加载窗口。
3. 执行真实 `EditorSession.do_save(False)`。
4. 返回 `True`，模型与磁盘都变为 `""`。

原因：`flush_surface()` 在页面未就绪时让 JS 返回 `null`；本机 PySide6 的 `runJavaScript` 回调将它转换为 Python 空字符串。`isinstance(result[0], str)` 因而通过，空文本被当成有效抓取结果。独立 `null` 探针也得到 `""` / `str`。这不是用户主动清空文档，且没有依赖实际磁盘写入失败。

建议：JS 返回明确的状态对象或带状态的 JSON，只有 `ready=true` 且捕获成功才采纳文本；将“有效空文档”和“未就绪/无返回值”区分。关闭标签、新建重置、退出也必须检查 `flush_pending_edits()` 的失败返回值，当前三个入口均忽略它。验收要求：有效空文档能保存，未就绪/超时/异常的页面不得改变模型、磁盘或关闭状态。

证据：`followup.unready_save`、`followup.real_failed_flush_close`；另有 `probe.failed_flush_close` 的失败返回值注入检查。关闭探针为隔离后续调用而重设了 dirty 标志，不将其当成无条件发生的正常关闭丢失结论；真实保存清空文件的结果不依赖该重设。

### P1-02：复杂列表直接保存会丢子列表，多段列表结构也会损坏

位置：[html_to_md.js:126](../mdnote/editor/web/html_to_md.js#L126)、[html_to_md.js:138](../mdnote/editor/web/html_to_md.js#L138)、[html_to_md.js:157](../mdnote/editor/web/html_to_md.js#L157)。

有效输入如下，真实页面包含两个子列表：

```markdown
- parent

    - first nested

    1. second nested

- sibling
```

未编辑直接保存后，`second nested` 从文件中消失。序列化只取 `nestedList(li)` 找到的第一个嵌套列表；其余列表被排除于正文，又未被遍历。松散列表的 `<p>` 及换行则被直接拼入 `- ` 后，列表内第二段无法保持原有结构。基础单层列表通过，不能代表这些场景无损。

建议：按原有节点顺序处理一个条目中的全部段落、代码、引用和子列表，保留段落间距与续行缩进。验收以打开→不编辑→保存→重开后全部文本和层级仍一致为准。

证据：`followup.extra_roundtrip.valid_multiple_nested.saved`、`probe.save_roundtrip.loose_list`。

### P1-03：列表项转换会把整个列表移到后续段落之后，且不能撤销

位置：[app.js:1037](../mdnote/editor/web/app.js#L1037)、[app.js:1061](../mdnote/editor/web/app.js#L1061)、[app.js:921](../mdnote/editor/web/app.js#L921)。

文档顺序为 `Before → 三项列表 → After`，对第二项执行标题转换或在项首 Backspace 转正文后，顺序变为 `Before → After → 拆开的列表与转换项`。执行真实 `App.undo()` 后仍然如此。

原因：拆分列表后使用 `parent.appendChild()` 把所有替换节点追加至父节点末尾，而非插回原列表位置；直接 DOM 操作未进入原生撤销历史。此前“兄弟列表项不消失”的修复有效，但未覆盖后续段落和撤销。

建议：保留原插入位置，并使用可撤销的编辑事务；同时验证嵌套列表、富文本和有序列表编号。证据：`followup.list_heading`、`followup.list_backspace`。

### P1-04：代码里的反斜杠会被当成正文转义并删除

位置：[surface.py:60](../mdnote/services/surface.py#L60)、[surface.py:70](../mdnote/services/surface.py#L70)、[html_to_md.js:44](../mdnote/editor/web/html_to_md.js#L44)。

原文 ``Use `\*literal\*` here``，真实保存结果为 ``Use `*literal*` here``。缩进代码 `    x = "\*literal\*"` 也丢反斜杠。围栏代码的原文保留路径不受这个例子影响。

原因：在 Markdown 解析前对整个普通块替换 `\X`，包括应按字面解释的行内及缩进代码；恢复成 span 后，代码序列化使用 `textContent`，无法还原反斜杠。

建议：转义保护必须识别代码语境，代码正文使用字面文本。证据：`followup.extra_roundtrip.escaped_inline_code.saved`、`indented_code_backslash`。

### P1-05：表格竖线被重复转义，重开后单元格错位并丢值

位置：[html_to_md.js:231](../mdnote/editor/web/html_to_md.js#L231)、[surface.py:70](../mdnote/services/surface.py#L70)。

表格数据行为 `| a\|b | c |`，页面正确显示 `a|b` 和 `c`。未编辑直接保存后变成 `| a\\|b | c |`。使用产品自己的 Markdown 引擎重解析时，两格变成 `a\` 和 `b`，`c` 消失。

原因：literal span 先输出 `\|`，`cellText()` 又对其中的 `|` 加一次转义。建议统一文本与单元格转义层次，不能对已经序列化的 Markdown 字符串再次全局转义。证据：`followup.extra_roundtrip.pipe_table`，含真实磁盘结果和前后渲染结果。

### P1-06：HTML 实体表示的普通文字保存后变成 HTML 或其他实体语义

位置：[html_to_md.js:35](../mdnote/editor/web/html_to_md.js#L35)。

原文 `&lt;em&gt;literal&lt;/em&gt;` 显示为普通文本 `<em>literal</em>`；真实保存后磁盘为 `<em>literal</em>`，再次打开将成为斜体。`&amp;copy;` 会变成 `&copy;`，`&lt;img src=x&gt;` 会变成实际标签语法。

原因：文本节点直接返回已经实体解码的 `nodeValue`。建议依据文本语境转义 `&`、`<` 等会改变 Markdown/HTML 语义的字符，并验证连续多次保存的稳定性。这是内容保真缺陷，本轮没有由此证明脚本执行漏洞。

证据：`probe.roundtrip.escaped_html`、`escaped_entity`、`probe.save_roundtrip.escaped_html`。
