## 1. 优先修复的 P1

### P1-01：关闭守卫看不到尚未同步的输入，原子块编辑甚至可以长时间保持“已保存”

- 位置：[main_window.py:219](../mdnote/ui/main_window.py#L219)、[main_window.py:901](../mdnote/ui/main_window.py#L901)、[app.js:226](../mdnote/editor/web/app.js#L226)、[app.js:242](../mdnote/editor/web/app.js#L242)。新建重置路径也仅检查 `session.dirty`（main_window.py:474）。
- 普通输入防抖 120ms 后才发送到 Python。实际在干净文档 `original` 后插入 ` NEW`，立即调用关闭标签：Python 仍为 `original`、`dirty=False`，保存确认守卫调用 **0 次**，标签被移除。
- 更稳定的复现：打开 `---\ntitle: old\n---`，进入 front matter 原子块编辑并追加 ` NEW`，等待 **400ms**。页面已有新内容，但模型仍为原文、`dirty=False`；关闭标签同样无提示丢弃修改。原因是 `onInput` 遇到 `activeAtom` 直接返回，只有显式提交才同步。
- 建议：关闭标签、退出窗口、重置前先读取/提交页面编辑状态，再计算 dirty 和询问保存；原子块开始修改时也应通知宿主。保存按钮已有 `flush_surface()`，应统一到所有离开文档的入口。

### P1-02：把一个列表项转为正文或标题，会删除其余列表项，而且不能撤销

- 位置：[app.js:877](../mdnote/editor/web/app.js#L877)、[app.js:938](../mdnote/editor/web/app.js#L938)。
- 输入 `- first\n- second\n- third`，将光标放在 `second` 开头并按 Backspace，得到的全文只有 `second`；再执行撤销仍只有 `second`。
- 同一位置执行标题转换，得到的全文只有 `## second`。两条路径都用当前条目的内容替换整个 `ul/ol`，并直接修改 DOM，绕过浏览器的编辑历史。
- 建议：只拆分/转换当前条目，保留前后条目和嵌套结构；将结构编辑纳入可撤销事务。现有单条列表测试无法发现此问题。

### P1-03：跨块引用链接与脚注在实时模式中失效，直接保存就能丢失定义

- 位置：[surface.py:59](../mdnote/services/surface.py#L59)、[surface.py:142](../mdnote/services/surface.py#L142)。每个块单独调用 Markdown 引擎，跨块定义不共享。
- 实测打开 `[website][ref]\n\n[ref]: https://example.invalid/ "Title"`，页面显示未解析的 `[website][ref]`，定义块不产生可保留的内容。
- **未编辑，直接调用真实 `EditorSession.do_save(True)`**，返回成功，磁盘只剩 `[website][ref]`，URL 和标题均被删除。
- 脚注 `A footnote[^n].\n\n[^n]: Footnote body.` 同样无法正确关联；回写变成普通脚注正文及失效返回链接。
- 建议：全文解析并保留引用/脚注上下文，或保存这些结构的原始 Markdown 并建立显式块映射。需要增加“打开→不编辑→保存→重新打开”的语义保真测试。

### P1-04：反向序列化无法保留文字转义、复杂行内代码和列表层级

- 位置：[html_to_md.js:35](../mdnote/editor/web/html_to_md.js#L35)、[html_to_md.js:128](../mdnote/editor/web/html_to_md.js#L128)。文本节点直接输出，行内代码固定单反引号，嵌套列表固定缩进两个空格。
- 真实页面捕获结果：

| 原内容 | 回写内容 | 影响 |
| --- | --- | --- |
| `literal \*asterisk\*` | `literal *asterisk*` | 普通星号变为强调语法 |
| `&lt;em&gt;literal&lt;/em&gt;` | `<em>literal</em>` | 普通文本变为 HTML 语义 |
| 双反引号包裹的 ``a`b`` | 改用单反引号包裹相同正文 | 代码分隔符失效 |
| 子项行首四空格 | 子项行首两空格 | 当前 Python-Markdown 引擎重新解析时丢失层级 |
| 有序列表从 `5.` 开始 | 重新编号为 `1.` | 忽略原有 `ol[start]` |
| 定义列表、`mark`、`sup` | 普通文字 | 结构和语义丢失 |

- 表格中的加粗/链接和普通代码围栏在本轮往返保持，不能把上述问题概括为所有格式都会丢失。
- 建议：区分正文转义和 Markdown 标记；根据内容选择代码分隔符；保留列表起始编号，按当前引擎规则序列化嵌套层级；不能无损处理的结构保留源码。
