# 新建页面与中文输入测试报告

测试日期：2026-11-03；基线：0.3.15（`72a28b7`）。测试环境为 Windows、Python 3.10、PySide6 6.11.1，WebEngine 自动化使用 offscreen 和禁用 GPU；用户提供的截图为浅色窗口中新标签编辑区显示黑色。

## 发现与复现

1. **输入法组字期间可能被格式化打断。** WebEngine 回归在正文粗体、列表、标题中发出 `compositionstart`，然后模拟 `isComposing=false` 的 input。修改前三种情况下均进入了格式转换入口，违反组字期间不执行该路径的约束；列表场景会在入口内部提前返回，本次未观察到它因此替换节点。真实输入法的事件顺序因输入法和 Chromium 版本而异；此测试复现的是代码层面的风险，并未证明它就是用户现场问题的原因。
2. **新页面黑色闪屏的根因尚未实机确认。** 代码原先将原生视图背景设为透明，页面声明支持系统深色配色；这两处均可能参与首次绘制的黑色背景。既有测试仅检查页面背景色属性，不能验证首次显示的实际像素。由于未采集用户同一显卡 / 系统配色下的逐帧画面，不能将截图归因于这两处或宣称完全复现。

## 修改

- 从 `compositionstart` 到 `compositionend` 持续保护组字，阻止未标记的按键、beforeinput 和 input 触发自动配对或格式转换；跳过配对闭合符后的延迟渲染也检查组字状态。组字结束后的格式化推迟到下一帧，且遇到新的组字时不执行。
- 新建 WebEngine 视图使用不透明的当前主题背景，主题切换时同步；取消页面跟随系统 `color-scheme` 的默认声明，由应用主题控制。

- 真实 QWebEngine 页面中的合成事件专项：修改前模拟未标记 input 的三个子场景失败；修改后专项通过。额外覆盖未标记的按键、自动配对、延迟渲染保护和视图背景配置。合成事件不能替代微软拼音或其他真实输入法的候选词、连续组字和上屏操作。
- JavaScript 全量：55 项通过。
- 首轮 Python 全量在与打包任务并行时出现失败并随后长时间无进展，已中止，不计为通过。独立运行 324 项：322 通过、1 个目录符号链接权限场景跳过、1 项失败；失败用例要求组字结束事件同步转换，和本次推迟至下一帧的行为冲突。已将该用例改为等待并检查最终标题，标题快捷键套件 14 项通过。最终全量复跑 324 项：323 通过、1 跳过，耗时 204.215 秒。
