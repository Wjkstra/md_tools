# 数据模型：块级文档模型

本文描述 MdNote 的核心数据结构——**块级文档模型（Block Document Model）**：
它如何切分 Markdown、如何保证可逆，以及编辑变换如何作用于它。

## 1. 为什么需要块模型

「渲染后编辑」要求文档具备结构化索引：

- 点击某块时，只需显示 / 提交**这一块**，而不必处理整篇文档
- 智能回车、行首合并等操作需要知道「光标落在哪个块、块内什么位置」
- 撤销重做需要以较小的代价记录文档变化

但 Markdown 本质是纯文本。MdNote 的做法是：**规范文本（canonical text）
是唯一事实源，块模型是它的可重建派生物**，二者严格可逆。

## 2. 模型结构

```python
@dataclass
class DocModel:
    text: str            # 规范文本（即原文）
    blocks: list[Block]  # 有序块列表
    gaps: list[int]      # 每个块内容之后的换行数（块间与文末）

@dataclass
class Block:
    id: str              # type|lang|raw 内容的 FNV-1a 哈希
    type: str            # 块类型
    start: int           # 内容起始偏移（含）
    end: int             # 内容结束偏移（不含尾随换行）
    raw: str             # 块原文 = text[start:end]
    lang: str | None     # 代码块语言
    level: int | None    # 标题级别 1~6
    trailing: bool       # 是否为文末挂尾空段落
```

### 块类型

| 类型 | 识别规则 | 渲染方式 |
| --- | --- | --- |
| `frontmatter` | 文档起始 `---`，闭合于 `---` 或 `...`（遇空行失效） | YAML 解析为键值表 |
| `code` | 围栏 ```` ``` ```` 或 `~~~`（允许 0–3 空格缩进），闭合符同字符且长度不小于起始符 | 语言标识 → Pygments；`mermaid` 走图表渲染 |
| `math` | 独立行 `$$` 配对，或单行 `$$...$$` | KaTeX displayMode |
| `heading` | ATX 风格 `#{1,6}` | 标题 + slug id |
| `blockquote` | 行首 `>`（允许空行后继续） | 引用块排版 |
| `list` | `-` / `+` / `*` / `数字.` / `数字)`；含缩进续行与松散列表 | 列表排版；`- [ ]` 识别为任务项 |
| `table` | 含 `\|` 的行 + 下一行是分隔行 `:?--` | 表格 + 可视化单元格编辑 |
| `hr` | `---` / `***` / `___`（或三个带空格的标记） | `<hr>` |
| `toc` | 独立 `[toc]`（大小写不敏感） | 从标题派生的目录 |
| `html` | 标签 / `<!--` / `<!DOCTYPE` / `<?` 起始，吃到空行 | 处理后输出 |
| `paragraph` | 其余情况，吃到空行或新块起点 | 普通段落 |

解析优先级（自上而下匹配）：frontmatter → code → math → hr → toc → heading
→ blockquote → list → table → html → paragraph。

## 3. 解析算法

`build_model(text)` 是**纯函数**，分两步：

### 3.1 行切分

一次扫描记录每行的起始偏移与去 `\r` 文本：

```
line_starts[i] = 第 i 行第一个字符在 text 中的偏移
line_texts[i]  = 第 i 行文本（不含 \n，去掉行尾 \r）
```

### 3.2 范围归并

游标 `cursor` 逐行推进，按上表规则识别块、吃掉属于该块的所有行
（多行块 = 一个范围 `[a, b)`），跳过空行。最后把行范围换算成字符偏移：

```
start = line_starts[a]
end   = line_starts[b-1] + len(line_texts[b-1])
raw   = text[start:end]
```

### 空文档与文末挂尾块

- 文档没有任何内容时，生成一个空段落块，保证始终有可点击的编辑落点。
- 无论文档多长，模型末尾**始终挂一个空段落块**（`trailing=True`），
  位于 `len(text)`，提供类似「文末空白行」的点击与编辑区域；
  它不改变序列化结果。

## 4. 偏移与间隙不变量

块的 `start/end` 只覆盖**内容行**；块与块之间的换行不计入任何块，
由 `gaps[i]` 单独记录。三条核心不变量：

1. **覆盖不变量**：按块与间隙拼接的结果恒等于原文

$$
\text{text} = \sum_{i} \bigl( \text{blocks}[i].raw + \texttt{'\n'}^{\,gaps[i]} \bigr)
$$

2. **顺序不变量**：`blocks` 按 `start` 严格升序，块区间互不重叠
3. **自洽不变量**：`block.raw == text[block.start:block.end]`

`serialize(model)` 依据不变量 1 重建文本，与原文逐字符一致——
这是「编辑可逆」的保证，并有对应的自动化测试（见 `tests/test_editor.py`）。

### 为什么 gaps 要独立存在

考虑：

```markdown
第一段

第二段
```

若把尾随换行并入块 raw，段落块在「一个 / 两个 / 零个换行」三种排版下
raw 都不同，缓存与差异比较都会失效。gaps 独立后：**内容变化与间距变化解耦**，
块渲染缓存按 raw 哈希命中，行高测量与间距互不干扰。

## 5. 标题与大纲

`extract_headings(model)` 扫描 heading 块：

- 去除前缀 `#`、尾部闭合 `#` 与内联标记（`` *_`~ ``）
- `slugify()` 生成锚点 id：小写、去标点、空白转 `-`
- 重名时自动追加 `-2`、`-3`…，保证 id 唯一

大纲、`[toc]` 块、导出目录、滚动当前章节都消费同一份标题列表。

## 6. 编辑变换

编辑动作不直接操作页面，而是生成 `TransformResult(text, caret)` 的
**纯函数结果**，由 `LiveDocument` 统一转成规范文本上的更新：

| 变换 | 触发 | 行为 |
| --- | --- | --- |
| `split_at` | Enter | 在光标处拆分：列表后半段进入同级新项（有序列表自动递增），空项回车取消格式；引用后半段进入新引用行；标题后半段成为普通段落；其他块在光标处换行 |
| `merge_with` | 行首 Backspace | 与上一块合并，光标落在接缝处 |
| `indent_line` | Tab / Shift+Tab（列表中） | 行首增 / 删缩进（宽度取设置） |
| `detect_space_trigger` | 输入空格 | 识别 `# `、`> `、`- `、`1. `、`- [ ] `、` ``` `、`~~` 等前缀，即时展开对应结构 |
| `wrap_selection` | 加粗 / 斜体等格式操作 | 用成对标记包裹选区；无选区时插入标记对 |
| `insert_at` | 图片 / 链接 / 拖放 | 在指定偏移插入字符串 |

> 智能回车的关键：**无论在块的什么位置按 Enter，都在光标处截断，
> 后半段移到下一行**；列表、引用会自动为下一行补上相同格式的前缀。

## 7. 编辑草稿（draft）

编辑某块期间，已提交的规范文本和块模型**保持不变**，正在输入的内容由
`LiveDocument` 作为一份**草稿**保存：

```python
_draft: tuple[int, str] | None   # (块索引, 当前输入文本)
```

- 页面每次内容变化调用 `updateDraft(index, raw)`；草稿只存在于内存
- 因为规范文本未变，编辑期间块索引、其它块的渲染都保持稳定，
  不会因为每次按键而重排整篇
- `get_text()` 返回「用草稿替换对应块后」的临时文本，因此保存 / 自动保存、
  字数统计读到的始终是包含当前输入的最新内容
- 离开该块时 `commit(index, raw)` 将草稿写回规范文本、重建块模型并清空草稿
- 若草稿与该块原始 raw 相同（未实际修改），则跳过重写

### 插入补偿：`_insertion`

某些位置提交时需要自动补齐分隔：

- 在**文末挂尾块**首次输入、且原文末尾没有空行时，自动在前面补 `\n\n`，
  保证新内容与上一块之间有正确的 Markdown 空行分隔
- 其余情况原样插入

补偿只改变实际写入的字符串长度，光标全局偏移会据此（`prefix_len`）重新换算。

## 8. 块标识与缓存

块 id = FNV-1a(`type|lang|raw`)。内容未变的块：

- 渲染结果可缓存复用
- 结构重建后可按 id 识别为同一块

任何字符修改都会改变 id，天然避免「显示了旧块内容」类问题。

## 9. 扩展块类型

新增一种块（如脚注块、定义列表块）的步骤：

1. 在 `block_model.py` 中新增类型识别：在游标循环、`paragraph` 兜底之前加入规则并给出范围
2. 如需占位高度，按类型在前端样式中处理
3. 在渲染管线中为该类型生成展示内容
4. 需要交互时在页面脚本中绑定控制器，并在离开块时正确提交
