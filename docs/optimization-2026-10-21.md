## 内容安全与保真

| 报告问题 | 修改后的行为 |
| --- | --- |
| P1-01 未就绪页面清空文件 | 捕获返回带 `ready` 和 `text` 的 JSON，严格验证类型。允许有效空文档；未就绪、异常、无回调和无效返回均拒绝采纳，超时后的回调被忽略。关闭标签、重置新建与退出均检查同步结果，失败时保留会话。正常加载中的页面有最多 1.2 秒的就绪等待。 |
| P1-02 复杂列表丢失 | 按 DOM 顺序序列化全部段落、引用、代码和嵌套列表，保留松散段落与续行缩进。软换行后的字面列表标记保持文字语义；序列化不再修改 DOM 文本节点。 |
| P1-03 列表转换乱序、不可撤销 | 使用原位置的单次原生编辑事务，保留富文本、嵌套列表及有序列表起始编号。额外覆盖文首列表的 Chromium 插入边界；支持撤销与重做。 |
| P1-04 代码反斜杠丢失 | 将转义处理接入 Markdown 行内解析阶段，代码语境先解析为字面文本，不再对整块源码做转义替换。 |
| P1-05 表格竖线重复转义 | 检查已有反斜杠的奇偶性，避免对已经序列化的竖线再次转义。 |
| P1-06 实体文字变成 HTML | 文本节点中的 `&`、`<` 重新编码；代码正文继续按字面输出。保存、重开及再次保存保持语义稳定。 |
