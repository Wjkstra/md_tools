## 1. 优先修复的 P1

### P1-01：编辑原子块时，外部文件变更可无提示覆盖未保存输入

位置：[app.js:323](../mdnote/editor/web/app.js#L323)、[main_window.py:830](../mdnote/ui/main_window.py#L830)。

复现：打开包含 `$$` 公式块的临时文件，点击公式进入源码编辑，用原生 `insertText` 增加文字，随后从外部更新文件。编辑后 `session.dirty` 仍是 `false`，模型保留旧文；`_on_external_change()` 只检查该标志，直接 `load_text(disk)`。实际观察：确认对话框调用 **0 次**，页面与捕获结果均只剩 `External replacement`，新增的 `REVIEWNEWATOM72941` 消失。

原因：`onInput()` 在 `activeAtom` 存在时直接返回，既不同步也不通知 Python 存在未提交修改；文件监视回调在覆盖前没有捕获页面内容。普通输入的 120ms 防抖窗口也应纳入同一保护设计，但本轮确定性证据是原子块输入。

建议：输入发生时立即维护可靠的修改状态；任何可能替换文档内容的外部重载都应先同步或检查待提交输入，并在冲突时保留本地内容。同步失败应拒绝覆盖。证据：`followup.external_atom`。

### P1-02：编辑原子块并首次保存后，后续输入不再同步，自动保存保持旧内容

位置：[app.js:185](../mdnote/editor/web/app.js#L185)、[app.js:326](../mdnote/editor/web/app.js#L326)、[editor_session.py:309](../mdnote/ui/editor_session.py#L309)。

完整用户路径：无标题文档中编辑公式源码，将 `x=1` 改为 `x=2`，首次保存到文件，然后在普通段落 `Before` 后输入 ` LATEST`。首次保存成功且页面已重新渲染；此时 `App.activeAtom` 仍指向已脱离 DOM 的旧元素：`active=true, connected=false`。

等待正常同步周期后，页面捕获为 `Before LATEST`，Python 模型与磁盘仍为 `Before`，dirty 仍为 `false`。开启自动保存并直接执行 `autosave()` 后，磁盘仍无 `LATEST`。`onInput()` 因残留的 `activeAtom` 持续提前返回，部分键盘逻辑也走错误分支。

建议：在页面重建、重置和文件切换前明确结束原子块编辑，重建后清理引用；判断活动编辑元素时校验 `isConnected`。验收覆盖首次保存、另存为、模式切换和外部重载后继续输入。手动保存/关闭前的强制捕获能保护部分路径，不代表自动保存正常。证据：`natural_reload`，另有 `probe.reload_then_type`。

### P1-03：含反引号围栏的缩进代码保存后被拆成其他 Markdown 结构

位置：[html_to_md.js:192](../mdnote/editor/web/html_to_md.js#L192)。

输入以下有效缩进代码，打开后不做编辑，直接真实保存：

```text
    ```
    inner
    ```
```

保存结果变为五行：三个反引号、三个反引号、`inner`、三个反引号、三个反引号。重新解析得到两个空代码块与普通段落，代码中的反引号已成为围栏。列表内的缩进代码也会发生类似损坏。

原因：`renderCode(pre)` 固定使用三个反引号，未考虑代码正文中的围栏。新 `.md-code` 路径已有动态围栏逻辑，普通 `<pre>` / 缩进代码路径仍使用旧实现；列表内转换成围栏还涉及解析器对嵌套代码的支持。

建议：优先保留原始缩进代码表示，或统一使用经过语境验证的安全序列化；不能只替换围栏长度后便假定嵌套列表有效。验收需同时检查正文、块类型和真实保存重开。证据：`followup.disk_roundtrip.code_backticks/code_in_list`。

### P1-04：源码模式另存为会改写缩进代码中的图片示例

位置：[image_service.py:127](../mdnote/services/image_service.py#L127)、[image_service.py:214](../mdnote/services/image_service.py#L214)。

旧目录存在 `x.png`，文档正文是四个空格开头的 `![](x.png)`，即一段代码示例。切换源码模式并另存为到其他目录，操作返回成功；磁盘中的代码变为四个空格开头的 `![](assets/x.png)`，并复制了图片。

原因：`_prose_segments()` 只保护围栏及行内代码，未识别缩进代码；图片搬迁对剩余字符串执行正则替换。这条路径即使全程使用源码编辑，也会改写用户代码。

建议：通过 Markdown 语法位置识别实际图片，完整排除代码区域；使用事务复制机制处理真实图片。证据：`followup.save_as_disk.indented_code`、`probe.save_as.indented_code`。
